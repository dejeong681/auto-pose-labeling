# Auto Pose Labeling

이미지 업로드 → 포즈 자동 라벨링 → 관절·박스 수동 검수 → TXT 저장/JSON 다운로드를 연결한 로컬 웹사이트입니다.

`auto-labeling`과 같은 **React + TypeScript + Vite**를 사용합니다. Python FastAPI는 모델 추론과 파일 저장을 담당하고, React는 이미지 목록·모달·편집 도구를 담당합니다. CSS는 `frontend/src/styles.css`로 분리되어 있습니다.

## 개발할 때 실행 (터미널 2개)

먼저 백엔드를 실행합니다. Python 패키지 설치는 처음 준비할 때만 필요합니다.

```powershell
cd C:\\\\Yt\\\\auto-pose-labeling
conda activate auto-labeling
python -m pip install -r requirements.txt
python -m uvicorn app:app --reload
```

다른 터미널에서 React 개발 서버를 실행합니다. Node.js가 필요하며 `npm ci`는 최초 설치 또는 패키지가 바뀌었을 때 실행합니다.

```powershell
cd C:\\\\Yt\\\\auto-pose-labeling\\\\frontend
npm ci
npm run dev
```

개발 화면은 **http://127.0.0.1:5173**입니다. FastAPI는 8000 포트에서 실행합니다. `vite.config.ts`의 프록시가 `/api`와 `/images` 요청을 FastAPI로 전달하므로 기존 API 주소와 이미지 주소를 그대로 씁니다. 두 서버 종료는 각각 Ctrl+C입니다.

백엔드 주소를 바꾸려면 `frontend/.env.local`에 `VITE\\\_API\\\_URL=http://127.0.0.1:다른포트`를 넣고 Vite를 재시작합니다. 이 값은 개발 프록시 설정이며 모델 경로와는 관계없습니다.

## 빌드한 화면으로 실행 (서버 1개)

```powershell
cd C:\\\\Yt\\\\auto-pose-labeling\\\\frontend
npm run build
cd ..
python -m uvicorn app:app --reload
```

이때는 **http://127.0.0.1:8000**에 접속합니다. `frontend/dist`에 생성한 화면을 FastAPI가 제공합니다. React 코드를 수정하면 다시 빌드해야 이 화면에 반영됩니다. `npm run build`는 TypeScript 검사도 함께 합니다. `npm run typecheck`로 타입 검사만 실행할 수도 있습니다.

React 개발 서버와 빌드 화면 모두 같은 데이터 폴더·API를 사용합니다. 빌드 전에도 API 서버는 실행할 수 있으며, 8000의 첫 화면에서는 빌드가 필요하다는 메시지를 반환합니다.

## 디렉터리 구조

현재 프로젝트는 루트의 Python 백엔드, `frontend/`의 React 화면, `data/`의 작업 데이터로 구성됩니다. 아래 트리는 주요 소스·설정 파일과 실행 과정에서 생성되는 폴더를 함께 표시한 것입니다.

```text
auto-pose-labeling/
├── README.md                  # 프로젝트 설명과 실행 안내
├── app.py                     # FastAPI 실행 진입점과 API
├── pose\\\_labels.py             # 라벨 검사와 TXT 읽기·쓰기
├── requirements.txt           # Python 패키지 목록과 버전
├── .gitignore                 # Git에 포함하지 않을 파일 설정
├── models/
│   └── \\\*.pt                   # 직접 준비하는 포즈 모델 가중치
├── data/
│   ├── images/                # 업로드한 원본 이미지
│   └── labels/                # 이미지별 YOLO TXT 라벨
└── frontend/
    ├── package.json           # 프론트엔드 패키지와 실행 명령
    ├── package-lock.json      # 설치 버전을 고정하는 파일
    ├── vite.config.ts         # 개발 서버와 API 프록시 설정
    ├── tsconfig.json          # TypeScript 검사 설정
    ├── index.html             # React가 연결되는 HTML 틀
    ├── src/                   # 직접 수정하는 화면 소스
    │   ├── main.tsx           # React 시작 지점
    │   ├── App.tsx            # 업로드·이미지 목록·모달 상태
    │   ├── api.ts             # 백엔드 요청 함수
    │   ├── types.ts           # 데이터 구조의 타입 정의
    │   ├── pose-editor.ts     # Canvas 좌표 계산과 편집 동작
    │   ├── styles.css         # 공통 화면 스타일
    │   └── components/
    │       ├── ImageList.tsx   # 이미지 썸네일 목록
    │       ├── EditorModal.tsx # 편집 모달과 작업 연결
    │       └── EditorTools.tsx # 사람·클래스·관절 편집 도구
    ├── node\\\_modules/          # npm ci로 설치되는 패키지
    └── dist/                  # npm run build로 생성되는 실행용 화면
```

`frontend/src/`는 개발자가 수정하는 소스이며, `frontend/dist/`는 그 소스를 빌드한 결과입니다. 빌드 화면을 바꾸려면 `src/`를 수정하고 다시 빌드합니다. `node\\\_modules/`와 `dist/`는 명령으로 생성되므로 직접 수정하는 대상이 아닙니다.

`models/`에는 Python 코드가 아니라 학습된 **가중치(Weights)** 파일인 `.pt`가 들어갑니다. 사용할 파일은 `app.py`의 `MODEL\\\_PATH`에서 선택합니다. `data/`에는 실제 작업 결과가 쌓이며, 예를 들어 `data/images/사진.jpg`의 라벨은 `data/labels/사진.txt`입니다.

`.git/`, `.vscode/`, `\\\_\\\_pycache\\\_\\\_/` 등 저장소·편집기·Python 캐시 폴더는 트리에서 생략했습니다. `node\\\_modules/`, `dist/`, 사용자 이미지·라벨, 모델 가중치는 `.gitignore`로 제외하며, `package-lock.json`은 설치 버전을 재현하기 위해 저장소에 포함합니다.

화면의 시작 흐름은 `index.html` → `main.tsx` → `App.tsx`입니다. 이미지를 선택하면 `EditorModal.tsx`가 열리고, 버튼·단축키의 동작을 `api.ts` 또는 `pose-editor.ts`에 전달합니다. React는 화면 구성과 상태를 관리하고, `pose-editor.ts`는 Canvas 그리기와 좌표 계산을 담당합니다.

자동 라벨링 요청은 `EditorModal.tsx` → `api.ts` → `app.py` → 포즈 모델 순서로 전달됩니다. 저장 요청은 같은 경로를 거쳐 `pose\\\_labels.py`에서 TXT로 변환된 뒤 `data/labels/`에 기록됩니다. 현재의 전체 자동라벨링 버튼은 일괄 처리 기능이 연결되기 전까지 비활성 상태입니다.

## 사용 순서

1. 이미지를 업로드하거나 목록의 썸네일을 눌러 편집 모달을 엽니다.
2. **자동 라벨링**으로 초안을 생성합니다. 저장된 라벨이 있으면 이미지를 열 때 자동으로 불러옵니다.
3. 처음에는 관절이 선택되어 있지 않습니다. 점을 클릭해 선택하고 드래그로 이동합니다. 빈 곳을 클릭하면 선택만 해제되며 기존 점은 이동하지 않습니다. 미지정 관절은 오른쪽 목록에서 선택한 뒤 이미지에 찍습니다. 좌우는 사람 자신의 좌우입니다.
4. 미지정 관절을 찍고 마우스를 놓으면 다음 번호의 관절이 자동 선택됩니다. 기존 점을 클릭하거나 드래그해 수정할 때는 다음으로 넘어가지 않습니다. 이미 지정된 다음 관절도 순서대로 선택하며, 마지막 16번 오른쪽 발목에서는 멈춥니다. \*\*선택 관절 미지정(0)\*\*은 좌표를 지웁니다. 보임·가림 선택 UI는 사용하지 않습니다.
5. 이미지의 **사람 박스 안이나 테두리를 클릭**하면 해당 사람이 선택되고 오른쪽 사람 목록·클래스 번호가 함께 바뀝니다. 겹친 박스는 작은 박스를 우선 선택하며, 관절 점을 누르면 관절 선택이 우선입니다. **클래스 번호 목록**에서 선택하면 즉시 편집 내용에 반영됩니다. 기본 목록은 `0`, `1`이며, 현재 이미지의 라벨에 다른 번호가 있으면 함께 표시합니다. 실제 파일 반영은 **저장** 또는 **Ctrl+S**로 합니다. **사람 추가** 또는 **박스 다시 그리기**를 누른 뒤 이미지에서 대각선으로 드래그합니다. 박스를 다시 그려도 관절의 이미지 좌표는 유지됩니다. 사람 삭제는 박스와 관절을 함께 지웁니다.
6. **저장** 또는 **Ctrl+S**로 서버에 YOLO TXT 라벨을 저장합니다. **다시 불러오기**는 저장된 TXT를 읽어 화면으로 복원합니다.
7. **JSON 다운로드**는 현재 편집 내용을 JSON으로 내보냅니다. 이 동작만으로 서버 TXT 라벨을 저장하지는 않습니다.

모달에서 **←는 이전 이미지, →는 다음 이미지**로 이동합니다. 목록에 보이는 순서이며 처음·마지막에서 순환하지 않습니다. 저장하지 않은 수정 내용은 버릴지 확인한 뒤 이동합니다. 저장·추론·불러오기·마우스 드래그 중에는 이동하지 않습니다. 입력칸이나 관절 목록에 포커스가 있으면 좌우 방향키의 원래 동작을 유지하며, Canvas를 클릭하면 이미지 이동 키를 다시 사용할 수 있습니다.

**↑는 이전 관절, ↓는 다음 관절**을 선택합니다. 관절 선택이 없으면 어느 방향이든 0번 코부터 시작하며, 0\~16 범위에서 순환하지 않습니다. Canvas나 관절 목록에 포커스가 있어도 동일하게 동작합니다. 클래스 번호 목록·사람 목록에서는 원래 방향키 동작을 유지합니다. 키를 누른 채 유지해도 반복 이동하지 않으며, 저장·추론·드래그·박스 그리기 중이거나 사람이 없으면 관절 이동을 하지 않습니다. 관절 선택만 바꾸는 것은 라벨 수정으로 처리하지 않습니다.

이미지 위에서 **Ctrl+마우스 휠**로 확대·축소합니다. 기본 이미지 표시 크기는 기존과 같으며 별도 확대 도구줄은 없습니다. 확대·축소 배율은 이미지 왼쪽 위의 반투명 표시로만 나타납니다. 마우스 위치를 기준으로 확대하며, 배율은 기본 표시 기준 25\~800%입니다. 다른 이미지를 열면 기본 배율로 돌아갑니다. 원본과 라벨 좌표는 그대로이며 화면에 표시할 때만 확대·이동을 적용합니다. 확대 중에도 점을 선택·드래그하거나 박스를 그릴 수 있습니다. 관절 목록에는 실제 17개 관절만 표시하며, 선택 해제는 빈 곳 클릭으로 처리합니다.

관절 점이 아닌 **배경을 왼쪽 버튼으로 누른 채 드래그**하면 사진 전체를 이동합니다(패닝). 관절이 선택되어 있었다면 먼저 선택을 해제하고, 같은 드래그로 사진을 이동합니다. 기본 배율에서도 이동하며 사진이 완전히 사라지지 않도록 각 축에서 40px 이상을 남깁니다(사진이 작으면 그 길이의 절반). 패닝 중에는 손을 쥔 커서가 표시됩니다. 박스 안에서 끌어도 사진을 이동하며 박스·관절 라벨 좌표는 바뀌지 않습니다. 미지정 관절을 목록에서 고른 경우에는 배경 클릭이 새 점 배치를 우선하고, 박스 그리기 모드에서는 새 박스를 그립니다. 패닝 중 Esc는 드래그 시작 위치로 되돌리고 모달은 유지합니다.

닫기·Esc·딤 배경 클릭으로 모달을 닫습니다. 수정 내용이 있으면 버릴지 확인합니다. 박스 그리기 중 Esc는 그리기만 취소합니다. 페이지를 새로고침하면 이미지 목록부터 표시합니다.

## 저장 구조와 라벨 형식

이미지 이름과 확장자·원본 바이트를 유지합니다. 한 장당 10MB까지 지원합니다. 같은 이름을 다시 업로드하면 별도 안내 없이 건너뛰고 기존 이미지를 표시합니다.

예: `사진.jpg`의 서버 라벨은 `data/labels/사진.txt`, 다운로드 파일은 `사진.json`입니다. 저장 버튼은 같은 이미지의 기존 TXT를 덮어씁니다. YOLO 학습에서 이미지와 라벨의 기본 이름이 같아야 하므로 원본 이미지 확장자는 TXT 이름에 붙이지 않습니다. `사진.jpg`와 `사진.png`가 함께 있으면 라벨 충돌을 막기 위해 요청을 거절하므로 이미지 이름을 구분해야 합니다. 이미지는 수정하지 않습니다.

다운로드 JSON에는 `schema\\\_version`, 원본 `filename`, 사람별 `class\\\_id`, `box: \\\[중심x, 중심y, 너비, 높이]`, `keypoints: \\\[{x,y,v}, ...17개]`가 들어갑니다. 좌표는 이미지 전체 크기 기준 0\~1입니다. 서버에 TXT를 저장할 때는 임시 파일을 다 쓴 후 교체합니다.

TXT는 사람 한 명당 한 줄이며 `클래스 cx cy w h x0 y0 v0 ... x16 y16 v16`으로 총 56개 값입니다. 사람이 없으면 빈 TXT입니다. `v=0`은 `0 0 0`으로 출력합니다. 17관절 개수, 좌표 범위, 클래스·상태 정수를 서버에서도 검사합니다.

이전에 만든 `사진.jpg.json`은 TXT가 없을 때만 읽습니다. 이 경우 수정 없이도 저장을 누를 수 있으며, `사진.txt`를 만들고 기존 JSON은 보존합니다. 두 파일이 있으면 TXT를 우선합니다. 잘못된 TXT를 발견하면 오류를 표시하며 오래된 JSON으로 대체하지 않습니다. 기존 파일을 일괄 변환하거나 삭제하지는 않습니다.

브라우저와 API는 계속 JSON 구조로 박스·관절 데이터를 주고받습니다. 서버 파일 저장 형식만 TXT입니다. `from\\\_yolo\\\_txt()`는 TXT를 편집 데이터로 복원하고 `to\\\_yolo\\\_txt()`는 편집 데이터를 소수점 8자리 TXT로 변환합니다.

학습 형식의 상태값 `v`는 유지합니다. **미지정은 0, 새로 지정한 관절은 2**로 저장하며, 기존 라벨의 1·2는 보존합니다. 편집 화면에서는 둘 다 '지정'으로 표시합니다. 모델 신뢰도는 정답 상태가 아닙니다. 자동 초안은 `usable=true`인 관절을 v=2로, 나머지를 v=0으로 변환하므로 사람이 반드시 검수해야 합니다.

COCO 포즈 모델의 자동 초안 클래스는 0입니다. 클래스 목록을 늘리려면 `frontend/src/components/EditorTools.tsx` 상단의 `CLASS_IDS` 배열에 번호를 추가합니다. 클래스 번호를 바꿀 때는 나중에 학습할 `data.yaml`의 번호와 일치시켜야 합니다. 현재 웹사이트가 낙상·비낙상 클래스를 자동 판단하지는 않습니다.

## 포즈 모델

`app.py` 상단 `MODEL\\\_PATH`의 `models/yolo11s-pose.pt`를 사용합니다. 파일이 없으면 \*\*모델 파일이 없습니다.\*\*만 표시합니다. 자동 다운로드나 다른 모델 대체는 하지 않습니다.

`DET\\\_CONF`, `KP\\\_CONF`, `IMGSZ`, `DEVICE`도 상단에서 설정합니다. 신뢰도 기준은 데이터로 조정할 임시값입니다. CPU로 실행하며 첫 추론 때 모델을 읽어 재사용합니다. 모델 파일을 교체하면 서버를 재시작하세요.

이미지의 관절을 다시 자동 라벨링하면 현재 화면의 편집 내용이 교체됩니다. 확인을 거치며 서버 라벨은 저장 버튼을 누를 때만 바뀝니다. 추론에 실패하면 기존 편집 내용은 유지됩니다.

## API

|요청|역할|
|-|-|
|`GET /`|웹 화면|
|`GET /api/images`|이미지 목록|
|`POST /api/images`|이미지 업로드|
|`POST /api/images/파일명/pose`|한 장 포즈 추론|
|`GET /api/images/파일명/labels`|TXT 라벨을 편집용 JSON 구조로 조회 (기존 JSON 호환 읽기)|
|`PUT /api/images/파일명/labels`|편집 데이터를 TXT로 저장·덮어쓰기|
|`POST /api/images/파일명/labels/export`|요청한 편집 내용을 다운로드 JSON으로 응답|
|`GET /images/파일명`|원본 이미지 표시|

API 설명은 실행 후 `http://127.0.0.1:8000/docs`에서 확인합니다. 현재는 본인 PC에서 혼자 사용하는 로컬 버전이며 DB 없이 파일로 저장합니다.
